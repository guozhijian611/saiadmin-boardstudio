# 安装与升级自动接入（2.1.1）

从 2.1.1 起，在插件管理中上传并安装 ZIP 即会完成语言与刷新保护接入。用户只需继续宿主原有的前端依赖安装和生产构建流程，无需额外运行接入脚本。服务器执行接入只依赖 PHP，不调用 Python、Node 或 shell。

## 实际生命周期

已验证的 saipackage 安装顺序是先复制后端/前端文件，再执行插件自己的 Phinx 迁移，最后处理依赖和安装状态。本版新增第九个迁移，在文件已到位时调用 `FrontendIntegration`：

1. 使用安装器的 `frontendDir()` 解析配置的前端目录。
2. 检查语言入口已复制、宿主结构、文件与目录写权限；先形成完整计划，再写任何宿主文件。
3. 锁定接入状态，按内容 SHA256 备份原文件，使用临时文件加原子替换写入两个管理片段。
4. 任一写入或状态记录失败，回退本次已成功修改的文件；如果此时文件又被其它进程修改，则保留外部修改并明确报告。

`src/main.ts` 中添加带管理标记的可选 eager glob；语言处理器仅对 `/boardstudio/` 路由跳过原有 `reload(50)`，保留 locale、语言持久化和其它页面行为。后续插件文件升级继续通过同一入口加载新资源；若未来接入契约变化，应追加迁移调用同一个幂等服务，不在应用启动或 migration init 中偷偷修改文件。

## 升级与卸载

2.1.0 无论是否执行过手动接入，都可升级。已知静态导入、可选 glob 和原刷新保护被接管，不叠加重复代码；自定义宿主无法识别时明确失败，不猜测覆盖。

卸载先检查全部插件业务表。存在记录时拒绝，宿主文件、菜单与数据保持不变。空库卸载移除本插件管理的片段并恢复原刷新调用；其它用户新增代码保留。不用整份旧文件覆盖宿主当前版本。管理片段若被用户修改，则拒绝静默清理，等待核对。

接入备份与状态位于 `server/runtime/boardstudio/frontend-integration/<前端目录哈希>/`，不随发行 ZIP 分发，卸载后保留。正常安装、升级、卸载不要求手工使用旧 Python 工具；可选 PHP 预览/修复命令见插件 README。

## 失败边界

这是安装阶段的显式源代码接入，部署用户必须有对应写权限。宿主使用不同组件路径或不同语言处理器时，安装将拒绝而非假成功；按错误核对版本与源文件再重试。接入回退只覆盖本次宿主文件修改，不宣称整个宿主安装器具有数据库/依赖/文件的分布式事务。

## 2.1.1 实测记录

2026-11-16，使用 SaiAdmin 6.1.5（基线提交 `b697986e7838dab87463c7597b2787cb3c0d1a7d`）、saipackage 6.1.0 的 Phinx 安装器、PHP 8.4，分别新建 MySQL 8.4 与 PostgreSQL 17 Docker 实验室。通过真实 HTTP ZIP 上传与安装 API 验收，不以手工复制或单独执行接入命令代替首次安装。两套环境均实际执行前端依赖安装。

| 场景 | 结果 |
| --- | --- |
| 双库全新安装 | 首次安装即生成两个管理片段、备份与状态；九个迁移完成 |
| 同版本上传 | 双库均按宿主约定拒绝重复版本，不重复写入 |
| 卸载后重新安装、幂等接入 | 不重复插入；保留安装后新增的用户代码 |
| 带业务数据卸载 | 拒绝卸载，两个宿主文件逐字节不变 |
| 空库卸载 | 清理自身片段，恢复刷新调用，保留用户其它修改 |
| 宿主结构不支持 | 自动接入失败，主入口无半成品修改，迁移停在八个；修复宿主后重试完成第九个迁移 |
| PostgreSQL 失败后事务 | 无遗留 idle in transaction 连接，后续重试成功 |
| 2.1.0 → 2.1.1 升级 | MySQL 覆盖旧版未接入，PostgreSQL 覆盖旧版已手动接入；大屏数据逐字段不变 |
| 宿主构建与类型检查 | 两套实际安装后的完整管理端均通过 Vite 构建和 vue-tsc；MySQL 空库卸载后完整构建仍通过 |

另通过 30 项 TypeScript 测试、插件 ESLint、PHP 语法及纯逻辑测试、播放器构建和发行包结构校验。PHP 接入回归覆盖只读预览、重复执行、旧接入接管、CRLF、文件不可写、第二个文件写入失败回退，以及拒绝覆盖用户改过的管理片段。主题与语言的浏览器交互历史记录见 [主题适配说明](theme-i18n.md)；本版不修改前端组件，本轮聚焦安装器自动接入与卸载生命周期。

测试入口 `tools/boardstudio/tests/auto_integration_http.py --help` 使用显式实验室、lab.py 和新旧 ZIP 路径，可在其它临时目录复用。该脚本会清空插件测试数据并卸载，只能用于已完成首次 ZIP 安装与真实依赖安装的独立可销毁实验室；`--manual-old` 用于覆盖旧版已手动接入的升级场景。它不会自动伪造首次安装的依赖完成状态；升级旧版时仅复用已安装且声明相同的依赖。
